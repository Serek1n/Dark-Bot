# История изменений

## Полная проверка бота и панели
**Безопасность панели**
- Роли для реакций, уровней, магазина и автороли теперь проверяются: нельзя выбрать роль интеграции, роль выше роли бота или своей собственной, а роли с правами модерации (бан, кик, управление сервером и т. п.) выдаёт только администратор или владелец. В списках такие роли видны серыми с причиной.
- Форум логов и канал оповещений можно выбрать только на своём сервере.
- Импорт уровней ограничивает числа из файла: огромное значение больше не может повесить бота.
- Защита от подделки запросов (CSRF) больше не принимает запросы с другого порта того же адреса.
- Сообщение об ошибке больше нельзя подставить через ссылку: в адресе передаётся только код ошибки.
- Не больше 25 оповещений и 100 своих команд на сервер.

**Панель**
- Если изменены сразу несколько блоков на странице, «Сохранить» сохраняет все, а кнопка одного блока спрашивает, сохранить ли остальные. Отправка сообщения через вебхук и размещение панелей больше не срабатывают с плашки «Сохранить».
- Ошибки Discord показываются по-русски. Слишком большая форма даёт понятное сообщение вместо «Внутренней ошибки».
- Если форум логов удалили, страница «Логи» говорит об этом. В оповещениях можно выбрать новостной канал. Проверяется логин Twitch.

**Бот**
- Итоги голосований с таймером считаются правильно (раньше всегда было 0 голосов).
- Музыка: остановленный плеер больше не остаётся в памяти; сломанные треки плейлиста не заваливают чат сообщениями (не чаще одного раза в 15 с).
- Время в голосе не начисляется тем, кто уже вышел, если Discord не прислал событие выхода.
- Временная комната удаляется, если владелец вышел до переноса в неё.
- `/mod warn|mute|unmute|kick|ban`, кнопки комнат и окна вебхуков сначала подтверждают нажатие, поэтому больше нет «Взаимодействие не удалось», когда Discord отвечает медленно. `/mod unmute` проверяет иерархию ролей, mute и unmute требуют права на тайм-аут. Временный бан ограничен 5 годами.
- Розыгрыш с тысячами участников проверяет только тех, кто выпал при жеребьёвке. Счётчик на кнопке обновляется не чаще раза в 5 с.
- Оповещения Twitch и YouTube не зависают на медленном запросе. Отозванный токен Twitch обновляется.
- Магазин сначала резервирует последний экземпляр, затем списывает деньги.
- Номера обращений не повторяются. Канал закрытого обращения удаляется и после перезапуска.
- Команды не показываются в личных сообщениях с ботом, а там, где они всё же вызваны, бот отвечает понятной фразой. Пункт меню жалобы называется «Пожаловаться». Права в сообщениях названы по-русски.

**Зависимости**
- `npm audit`: 0 уязвимостей. Обновлён `body-parser`, через `overrides` подняты `tar` (для @discordjs/opus) и `uuid` (для sequelize). Убран ненужный `concurrently`, `npm run dev` теперь `node --watch`.

## Доработки
- **Токен вебхука логов шифруется** в базе (AES-256-GCM). Ключ — `DATA_KEY` из `.env`, а если его нет — `SESSION_SECRET`. Миграция `0005` зашифрует уже сохранённые токены сама. Не меняйте ключ: иначе токен не прочитается и форум логов придётся подключить в панели заново.
- Пользовательские команды берутся из кэша, а не из базы на каждое сообщение; кэш сбрасывается при изменении в панели.
- Снимок участника при выходе сохраняется одним upsert-запросом.
- Карточка профиля кэшируется на минуту (формат webp измерен — медленнее PNG, оставлен PNG).
- Новая галочка в «Модерации»: автонаказание применяется, только если у модератора есть нужное право (миграция `0004`).
- Убраны все предупреждения ESLint.

## Вебхуки — в релизе
- Вебхуки (`/webhook`, панель вебхуков в Discord, раздел сайта) вышли из беты: работают на всех серверах и в любой версии бота, включены по умолчанию (выключить можно в разделе «Функции»). Сейчас в бете нет ни одной функции; механизм остаётся для следующих.

## Релиз и бета
- Бета-функции работают только в бета-версии: бот определяет ветку git (`beta`) или `BOT_CHANNEL`. На релизе они выключены, переключатель в панели заменён пояснением; в бета-версии рядом с названием в меню значок «бета».
- `scripts/update.sh main|beta` — обновление сервера до нужной ветки.

## Архитектура
- **Бот и панель — один процесс.** Каналы, роли и серверы панель берёт из кэша бота (без запросов к Discord), настройки применяются сразу, замки работают для всего. Отдельный процесс `dark-web` не нужен (`pm2 delete dark-web`). Сбой панели не останавливает бота.
- `web/routes/dashboard.js` (923 строки) разбит на 16 файлов в `web/routes/dashboard/`, общие помощники — в `web/utils/common.js`; дубль `hasManageAccess` убран.
- Миграции на **umzug** (`db/migrations`, таблица `schema_migrations`) вместо ручного списка ALTER. Убраны дубли колонок в модели `GuildSettings`.
- Единый **планировщик** (`bot/utils/scheduler.js`): розыгрыши, напоминания, опросы и временные баны срабатывают в срок и не опрашивают базу по таймеру.
- Сессии входа хранятся в основной базе (`web_sessions`), `connect-sqlite3` и второй sqlite3 убраны. После обновления все войдут в панель заново один раз.
- ESLint (`npm run lint`), проверка в CI.

## Музыка и голос
- Плейлист режется до 100 треков.
- Заглушённые (микрофон или звук выключены) не получают награду в голосе и не считаются «компанией» для минимума людей — галочка в разделе «Уровни» (по умолчанию включена).

## Надёжность баланса
- Монеты и кристаллы меняются только атомарными SQL-запросами («баланс = баланс − сумма, если хватает»), а не «прочитать → изменить → сохранить». Это закрывает дюп валюты: параллельные /pay, магазин, /daily, опыт из чата и голоса и панель (отдельный процесс) больше не затирают друг друга.
- /pay — одна транзакция (списание + зачисление); /daily — проверка «прошли ли сутки» внутри самого UPDATE; магазин сначала списывает деньги, потом выдаёт роль и возвращает деньги, если роль выдать не удалось.
- Уровень и кристаллы за уровень начисляются отдельным запросом «только если сохранённый уровень ниже» — дважды не выдаются.
- Транзакции процесса идут по очереди, на каждом соединении SQLite задано ожидание занятой базы.
- /daily больше не пишет «60 мин» вместо «1 ч 0 мин».

## Проект
- package-lock.json теперь в git (одинаковые версии при каждой установке); `@discordjs/opus` — необязательная зависимость.
- Docker: Node 22, yt-dlp, запуск не от root, порт только на 127.0.0.1.
- LICENSE (MIT), CI на GitHub Actions, кроссплатформенная очистка тестовых баз, исполняемые тестовые .sh.

## Оформление панели
- Мягкий свет в углу рабочей области, карточки с объёмом и крупными скруглениями, заголовки страниц крупнее.
- Обзор начинается с самого сервера (значок или буква названия, имя).
- Выбор сервера: крупные плитки с буквой вместо картинки, если у сервера нет значка. Битый значок тоже заменяется буквой.
- Вход: луна со свечением — главный акцент страницы.
- Поля и кнопки: единое кольцо фокуса, одинаковые строки «вкл/выкл», товары магазина — раскрывающиеся строки.
- Мобильный вид: меньшие отступы, одна колонка в формах.
